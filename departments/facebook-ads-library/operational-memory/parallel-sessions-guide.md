# Parallel Sessions Guide — 2 Claude Code Sessions с одним VPS

**Цель:** ускорить research за счёт параллельных Claude Code сессий при одном VPS и одном FB аккаунте.

**Ограничение:** Scraper использует один FB аккаунт (Mikhail Piatsiuk) + один IP. Два скрапера одновременно = двойная нагрузка на сессию → риск rate limit и потери cookie.

**Правило: scraper только последовательно. Всё остальное — параллельно.**

---

## Безопасная схема: 2 сессии

### Подготовка (один раз)
1. Открыть **два окна Claude Code** (VS Code или Web — любые)
2. Обе сессии работают с одним и тем же репозиторием и VPS
3. Одна сессия — **"активная"** (держит scraper lock), вторая — **"аналитическая"**

### Координация через lock-файл на VPS

Перед запуском скрапера активная сессия создаёт lock:
```bash
ssh -i ~/.ssh/market_research_vps root@5.78.217.133 \
  "echo 'session_A_keyword_baby_swaddle' > /tmp/scraper.lock"
```

Вторая сессия проверяет перед запуском:
```bash
ssh -i ~/.ssh/market_research_vps root@5.78.217.133 \
  "cat /tmp/scraper.lock 2>/dev/null || echo 'FREE'"
```

Если ответ `FREE` → можно запускать. Если есть содержимое → ждать или взять другой keyword.

После завершения скрапинга — удалить lock:
```bash
ssh -i ~/.ssh/market_research_vps root@5.78.217.133 "rm /tmp/scraper.lock"
```

## Пошаговый workflow двух сессий

```
SESSION A                          SESSION B
─────────────────────────────────  ─────────────────────────────────
1. Проверить lock → FREE           1. Запустить (параллельно с A)
2. Создать lock "session_A"        2. Пока A скрапит → готовиться:
3. Запустить scraper keyword_1        - читать context files
   (500 ads, ~60-90 сек)              - планировать следующий keyword
4. Scraper завершён                3. Проверить lock → занято
5. Удалить lock                       - ждать или делать что-то другое
6. Начать fast filter + verify     4. Lock снят → создать lock "session_B"
   (WebFetch — параллельно OK)     5. Запустить scraper keyword_2
7. Checkpoint → Marina feedback    6. Session B скрапит
8. Notion + commit                 7. Session B filter + verify
                                   8. Checkpoint → Notion + commit
```

### Ключевые моменты
- Scraper output session A: `/tmp/keyword1_results.json`
- Scraper output session B: `/tmp/keyword2_results.json`
- Разные имена файлов — нет конфликта

## Что МОЖНО делать параллельно (без риска)

| Действие | Параллельно? |
|---|---|
| Запуск scraper | ❌ ТОЛЬКО последовательно (один за раз) |
| WebFetch верификация кандидатов | ✅ Безопасно — не касается FB session |
| WebSearch проверка брендов | ✅ Безопасно |
| Notion cards создание | ✅ Безопасно |
| Git commit/push | ✅ Безопасно (разные ветки или по очереди) |
| Анализ результатов, scoring | ✅ Безопасно |
| Обновление файлов (learnings.md и др.) | ⚠️ Координировать — не редактировать одновременно один файл |

## Важные предостережения

**Одновременное редактирование файлов:**
Если обе сессии пишут в `learnings.md` или `reported-products.md` одновременно — возможен конфликт. Решение: сессия A пишет, сессия B ждёт или пишет после. Обе должны делать `git pull` перед записью.

**Cookie session:**
Один FB аккаунт. Если одна сессия обновила cookie → вторая должна знать об этом.
Рекомендация: обновлять cookie только один раз в начале дня, обе сессии используют одну версию `/opt/market-research-agent/cookies/fb_session.json`.

**Lock-файл — дисциплина:**
Если сессия завершилась с ошибкой и не удалила lock → вторая будет ждать вечно.
Проверка: `cat /tmp/scraper.lock` → если lock старый (>30 мин) → безопасно удалить вручную.

## Будущий апгрейд (когда нужна настоящая параллельность)

Если понадобится запускать 2-3 скрапера одновременно → нужен второй FB аккаунт + опционально второй VPS.
- Второй VPS: ~€3-5/мес (Hetzner, тот же провайдер)
- Второй FB аккаунт: доверенный человек (родственник, друг)
- Схема: сессия A → VPS-1 + account_1, сессия B → VPS-2 + account_2 — полностью независимы

До этого апгрейда: текущая схема (sequential scraper + parallel analytics) даёт ~40-50% ускорения при нулевом риске.
