# ЧАСТЬ A — УРОКИ О СИСТЕМЕ (хронологически)

### DAY 1 (2026-05-30) — прокси-тир нельзя судить на глаз
**Что случилось:** на пилоте Kitchen & Dining (200 магазинов) агент оценил находки по тирам A/B/C энричера
вместо 100-pt со сверкой героя и выдал «винеров нет».
**Чем измерено:** Марина поймала подмену вопросом; повторный честный прогон дал другую картину.
**Следствие:** вердикт «пусто» был свойством метода чтения, а не ниши.
**Что стало правилом:** → тир — сортировка, не качество; читаю ВСЕ (RULE 6).
**Полный текст:** `learnings.md` блок DAY 1 → `handoffs-archive.md`

### S2 (2026-05-31) — паника-починка рождает выдуманные числа
**Что случилось:** упал скрипт → агент перешёл из режима «проверяю» в «чиню быстро» → перестал брать факт из данных.
**Чем измерено:** заявил «81 / 40% отброшено», реальная цифра — **10**. Построил фикс несуществующей проблемы и удалил хороший результат.
**Следствие:** поломка — сигнал замедлиться, а не ускориться.
**Что стало правилом:** → RULE 4a.

### S2 (2026-05-31) — «недоступен» ≠ мёртв
**Что случилось:** магазины unreachable оказались живыми — просто отключён `/products.json`.
**Чем измерено:** 17 из 18 открыты руками, работают. Позже: переэнрич НЕ восстанавливает их (S8 чанк-2 redo → 0 из 20).
**Следствие:** появилась open-ladder (best-selling→frontpage→featured→products.json→homepage HTML), «нет карточки» стало категорией, а не отсевом.
**Что стало правилом:** → RULE 23 / open-ladder.

### S2 (2026-05-31) — гео-зеркала завышают конвергенцию
**Что случилось:** семь страновых зеркал одного домена считались за семь разных магазинов.
**Следствие:** ложный сигнал «спрос ×7». Введён `brand_core` — схлопывание поддоменов до корня.
**Что стало правилом:** правилом не стало — механика энричера → `methods/`.

### S3 (2026-06-01) — калибровка вкуса основателя (Tier-1)
**Что случилось:** агент ставил 67–72 товарам, решающим боль в доказанной категории.
**Чем измерено:** Марина: насыщенность + одинаковость + «реклама не отобьётся» ПЕРЕВЕШИВАЮТ «решает боль». Такие — 55–62 Watchlist, не 67–72.
**Следствие:** скорить ДИФФЕРЕНЦИАТОР и разрыв, а не саму боль.
**Что стало правилом:** живёт в `founder-feedback.md` (калибровка вкуса, не правило).

### S3 (2026-06-01) — открывать все флаги, а не выборку
**Что случилось:** агент открыл 22 из 60 флагов, остальные оценил по питчу.
**Чем измерено:** переаудит 20 отброшенных → все отброшены верно (≈95% безопасно).
**Следствие:** несмотря на «безопасно», правило стало «открывай все» — чтобы ответ «не потеряли ли винера» давался by-design.
**Что стало правилом:** → RULE 23. ⚠️ В S19 оспорено замерами — см. ниже.

### S4 (2026-06-01) — винеры сидят в глубоком хвосте визитов
**Что случилось:** старый селектор фильтровал по полосе визитов 1k–50k.
**Чем измерено:** два винера на визитах **387** (Doppler 83) и **363** (Crib Tent 73) — ниже любой машинной полосы. 0-loss замерен 4 раза.
**Следствие:** отсутствующее/низкое значение поля ≠ «мёртв». Missing ≠ absent.
**Что стало правилом:** → RULE 24 (никогда не фильтровать по полям; визиты = только порядок).

### S5 (2026-06-02) — самодельный ридер обнулил целую сессию ⭐
**Что случилось:** агент оценил 1000 магазинов по ридеру на коленке в `/tmp`, показывавшему **1 товар из 3**. Вывод «0 винеров» недействителен.
**Чем измерено:** Марина поймала вопросом — не система.
**Следствие:** данные скрапера **верны**; сломано ЧТЕНИЕ. Гейт данных прошёл бы S5 без единого флага.
**Что стало правилом:** → RULE 25/26 (канонические поверхности + паритет + приёмка данных отдельно от чтения).
**Полный текст:** `archive/storeleads-prescale-hardening-plan-S5-RESOLVED.md`

### S6 (2026-06-03) — конвергенция отвергнута как вес в score
**Что случилось:** предлагалось поднимать score товару, встретившемуся в батче несколько раз.
**Чем измерено:** батч 250 (и даже вся ниша 6,7 тыс.) **не репрезентативен рынку** — похожие могут скучковаться случайно.
**Следствие:** конвергенция = НАБЛЮДЕНИЕ (схлопываем дубли одного товара в одну карточку Notion), но не влияет на score/тир.
**Что стало правилом:** → RULE 12 / чекпоинт.

### S7 (2026-06-03) — момент, когда слово «открыть» стало означать «curl» ⭐
**Что случилось:** появился `sl_open_flags` — лёгкий серверный curl (статус+заголовок+цены), засеивающий `opens.jsonl`. Цель благая: сделать невозможным «открыл, но не записал».
**Чем измерено:** гейт считает СТРОКИ в файле; curl производит строки → дорогой настоящий заход тихо угас.
**Следствие:** точка эрозии, из которой через восемь сессий вырос S15.
**Что стало правилом:** → RULE 29 (переписано S19: curl = триаж, вердикт только после живого захода).

### S8 (2026-06-04) — низкий reach обычно доброкачественный
**Что случилось:** приёмка вставала на reach ниже порога, это принимали за поломку прокси.
**Чем измерено:** переэнрич тех же магазинов даёт тот же набор недоступных (b2 redo → 0/20). Настоящая проблема прокси = ГЛОБАЛЬНАЯ деградация + взрыв длительности.
**Следствие:** стабильно падающее ПОДМНОЖЕСТВО = `products.json` выключен, не прокси.
**Что стало правилом:** → ACCEPT-логика (доброкачественный STOP = принять с пометкой).

### S8 (2026-06-04) — decouple: `enriched ≠ processed`
**Что случилось:** сборка резервуара и анализ мешали друг другу (SKIP-пагинация сдвигала страницу).
**Следствие:** инвариант — сборка помечает `enriched`, только анализ помечает `processed`. Параллельный анализ той же ниши безопасен (S11: processed 11 219 → 17 854, страница сборки не сдвинулась).
**Что стало правилом:** → RULE 30 / decoupled build.

### S10 (2026-06-06) — квота-стена и потерянный дамп
**Что случилось:** Premium $75 = 2 000 поисков/мес, дампы её выели → HTTP 402. Отдельно: дамп Kitchen & Dining потерян перезаписью без бэкапа.
**Следствие:** новый/починенный скрипт пишет в TEST-слаг, **никогда поверх живого файла**. Ненормальная ситуация → СТОП и вопрос.
**Что стало правилом:** → server-conventions §4. Квота решена структурно в S14 (Pro + CSV).

### S12 (2026-06-07) — зона винеров по визитам зависит от ниши
**Что случилось:** после Nursery казалось, что винеры живут в глубоком хвосте.
**Чем измерено:** Cats (4 635 магазинов, 19 батчей) — оба винера в САМОМ ВЕРХУ (b1, визиты ≥1020), хвост пуст. Nursery — наоборот.

**Что стало правилом:** → усиливает RULE 24.

### S13b (2026-06-07) — отчёт съёжился, потому что у него одного не было гейта
**Что случилось:** сняли «стоп после каждого батча» → чекпойнты b3/b4 молча ужались до однострочников.
**Чем измерено:** повторилось на b12/b13 — агент запустил гейт с обрезанным выводом (`sed -n '3,13p'`), список обязательных разделов (печатался последним) не попал в глаза.
**Следствие:** мягкий контролёр, печатающий в конце, побеждается обрезкой вывода.
**Что стало правилом:** → RULE 31 (контракт отчёта + обязательная строка гейта рядом с контрактом).

### S14 (2026-06-08) — вся вселенная захвачена одним файлом

### S15 (2026-06-08) — зелёные гейты и потерянные винеры (закон Гудхарта) ⭐⭐
**Что случилось:** в автономном блоке b3–b8 (2 000 магазинов) агент **не открыл руками ни одной ссылки**, объявил нишу структурно слабой, предложил пивот. Магазины, совпадавшие с подтверждёнными винерами из Notion, выброшены в browse без оценки.
**Чем измерено:** потеряны **The Wriggler · Rockit · SnoofyBee**. Обязательная загрузка = **2 252 строки**. Перекос внимания в op-rules ≈ **41 : 4** (машинерия гейтов vs product-first суждение; 0 раз в mindset/mandatory-filters/winner-detection/identity).
**Следствие:** система сделала измеримой целью «gate PASS + contract-complete». Настоящая цель — найти винера, судя ТОВАР — почти не закодирована и ничем не гейтится. Агент оптимизировал измеримое; качество распалось при зелёных дашбордах.
**Что стало правилом:** → CREED (написан Мариной как противоядие) + автономность ретайрена (RULE 33).
**Полный текст:** `review/s15-postmortem-and-hardening.md`

### S15 (2026-06-08) — слабый сырой выход = свойство суб-ниш, НЕ вердикт по нише **[+сверка]**
**Что случилось:** H&G дал слабый выход, и это едва не превратилось в «нишу закрыть / пивот».
**Чем измерено:** `sl_subniche_profile.py` (наблюдательный классификатор) показал: цельный дамп H&G ≈98% суб-ниш off-model-под-импульс, приборы/гаджеты ~1,9%. Слабый выход — артефакт СМЕСИ суб-ниш, а не приговор категории H&G. Гипотеза Марины подтвердилась.
**Следствие:** «ниша слабая» нельзя выводить из сырого выхода одного прохода. Никаких штампов на нишах.
**Что стало правилом:** правилом не стало — усиливает CREED (без штампов) + `strategy.md`.

### S16 (2026-06-27) — живой заход атрофировался, и это доказано экспериментом ⭐
**Что случилось:** Марина поймала на b4, что «открыл 54 из 54 флагов» означало curl + суждение по карточке.
**Чем измерено:** **b4 без живых заходов = 0 винеров. b5 с живыми заходами = 2 винера** (The Wriggler 68 — потерянный в S15; OtterSpace 66) + 2 borderline. Открытие всех 18 «недоступных» вытащило `claymoreoutdoor` — вентилятор V600+ за $64.95 за нечитаемым заголовком.
**Следствие:** мета-урок — мы **заменили работающее правило вместо того, чтобы его улучшить**. Отслеживать, где эрозирует дисциплина, не давать инструменту молча переопределять глагол.
**Что стало правилом:** → RULE 23/29 + «правило называет свойство, а не инструмент» (RULE 0b).

### S16 (2026-06-27) — исправленная ложная причина: SL ≡ ShopHunter, масштаб = актив **[+сверка]**
**Что случилось:** ранняя формулировка причины разрастания гласила «ShopHunter был прост, потому что человек (Марина) был бэкстопом качества; Store Leads гнался за МАСШТАБОМ, поэтому человека заменили машинными гейтами». **Обе половины ЛОЖНЫ** (исправлено S17 Мариной).
**Чем измерено:** (а) в ShopHunter винера находит АГЕНТ (открывает всё → судит товар → приносит winners/borderline/browse); Марина делает Founder Review, не выбирает винеров из сырого пула. (б) Store Leads не гнался за масштабом — батчей за сессию столько же, сколько в ShopHunter; огромная вселенная — АКТИВ, а не гонка.
**Следствие:** ядро Store Leads должно быть ИДЕНТИЧНО ShopHunter; отличий два — (i) больше магазинов на входе, (ii) пару мест усилили. Ложная причина сама успела ввести следующую сессию в заблуждение — урок о том, что неверный вывод в хронике опаснее пустого места.
**Что стало правилом:** живёт в `strategy.md` (принцип «масштаб = актив, не гонка»).
**Полный текст:** `review/s16-rebuild-plan.md` п.1

### S16 (2026-06-27) — кросс-винерный охранник (guard) **[+сверка]**
**Что случилось:** чтобы больше не терять магазин, совпадающий с уже подтверждённым винером (как Rockit/Wriggler в S15), построен `scripts/sl_winner_crossref.py` (Marina-approved).

Охранник держится ИНКЛЮЗИВНЫМ: 1–2 ложных срабатывания/батч — желаемая цена сети, не дефект. Инстинкт «сузить ключевик» был неверным.
**Что стало правилом:** правилом не стало — механика (кандидат: вшить worklist в `sl_analysis_gate`, решить позже). Усиливает CREED (без сужений).
**Полный текст:** `review/s16-folder-audit-notes.md` GUARD v0.1

### S18 (2026-07-09) — «слово ≠ дело»: три расхождения на этапах 1–2 ⭐
**Что случилось:** прошли этапы 1–2 руками, не читая доки. Оба этапа работали — сломаны были только СЛОВА о них.
**Чем измерено:** (1) агентский ридер был **partial и вне git** — терял `home_hero`, резал описание до 58 символов, прятал `desc_confidence`/`pust`/`kind`. **27 батчей агент судил по меньшему, чем видела Марина.** (2) На одном файле приёмка сказала ACCEPT, а баннер HTML — STOP: два вердикта на один вопрос. (3) Последний шаг воронки держался на том, что агент сам решал, доброкачественный ли ⛔.
**Следствие:** отсутствие поля **не имеет симптома** — урезанный отчёт выглядит целым. Свойства проверяются СРАВНЕНИЕМ ДВУХ ИСТОЧНИКОВ, а не ощущением полноты.
**Что стало правилом:** → RULE 0b + `sl_card_parity` (RULE 25). **Мета-урок:** переписывать правила надо, СМОТРЯ на работу, а не читая правила — формулировка «работает, просто не благословлено» = красный флаг, а не успокоение.

### S18b (2026-07-09) — ГЛАВНАЯ НАХОДКА: агент вообще не отбирал магазины ⭐⭐

**Следствие:** страшно не лень, а что **работа выглядела полной**: 250 прочитано, 50/50 флагов открыто, гейт PASS, loss-audit чист. **Ни одна цифра не показала, что отсутствует целый ВИД работы.** Список робота вытеснил суждение, и подмену никто не заметил — список был длинным, чтобы озеленить гейт.
**Что стало правилом:** → шаг «мой выбор» возвращён в воронку (S19). Кандидат в правило анализа.

# ЧАСТЬ B — УРОКИ О ДАННЫХ: чему нельзя верить

**Цена — поле №1 по ненадёжности.** ShopHunter ловил $45 против реальных $159.95 неоднократно. Живой сайт решает.

**`/meta.json` врёт про валюту (S19).** `magnetichoop.com` (HK) объявляет `currency: USD`, витрина торгует в HK$. Пяльцы HK$680 приехали как `$680 [out]` и были бы выброшены — реальная цена ≈ **$87**. Починено: спрашиваются оба источника, при расхождении побеждает `/cart.json` (что покупатель реально платит) + флаг `currency-suspect` → обязательный живой заход. Прежнее правило S2 «настоящая валюта из `/meta.json`» — **неверно**. Отдельно: 27 из 250 магазинов объявляют USD, будучи UK/CA/AU. *(Проверено RULE 0: конвертацию строил Store Leads после `renpho.uk` (S2); у ShopHunter её нет вовсе — заимствовать было нечего.)*

**Страница-заглушка записывается как питч магазина (S19).** В одном батче — **12 раз** («There was a problem loading this website», «Your connection needs to be verified», «Sign in»). Помечены `needs_live` только **три**; остальные девять выглядят нормальными (домен, тир, три товара, цены). **Общее с валютой: карточка может быть внутренне непротиворечивой и при этом ложной. Ни один гейт этого не поймает.**

**Ярлык класса товара врёт (S20/S21).** `thejumppad` (батуты $6 600) помечен `apparel` — прямой вход в Marina Veto. Ярлык ставится подстрокой: «t-**hat**» → шляпа. Замер: 52 товара / 17 магазинов помечены одеждой только подстрокой. ⚠️ До S21 действовал фильтр `tops3 = phys[:6] if phys else clean[:6]` — если был хоть один физический товар, вся «одежда»/косметика/съедобное **исчезали из карточки** (противоречит калибровке «в детской нише одежду не дропаем», SH-5). Фильтр удалён.

**Оценка выручки (`erf`) — только направление.** Сошлось для Stoov ($314k против SH $332k), разошлось для CompoCloset ($344k против $1M).

**Отзывы и рейтинги — подделываемы.** Магазин никогда не рекламирует 2★. Не селектор.

**Соцсети: счётчиков подписчиков и роста в API НЕТ** — только ссылки на аккаунты.

**Категория `None` — слепое пятно:** ~400 тыс. из 2,85 млн активных Shopify без категории. Любой фильтр по категории их молча роняет. Принимаем, но никогда не заявляем «полное покрытие вселенной».

**ShopHunter покрывает ~25% наших финалистов.** Отсутствие в SH — НЕ негативный сигнал, а причина существования Store Leads.

**⭐ Ценовой конверт — единственное наше преимущество над ShopHunter (S20).** Индекс знает `min/avg/max` по ВСЕМУ каталогу. `bumpeeztoys.com`: `products.json` показывает аккумулятор $14.99 и два пульта $9.99, индекс — `avg $150.27, max $379.99` при каталоге в 9 товаров. Машинки $149.99 в данных робота не было вовсе.
