# ЧАСТЬ A — УРОКИ О СИСТЕМЕ (хронологически)

### DAY 1 (2026-05-30) — прокси-тир нельзя судить на глаз
**Что случилось:** на пилоте Kitchen & Dining (200 магазинов) агент оценил находки по тирам A/B/C энричера
вместо 100-pt со сверкой героя и выдал «винеров нет».
**Чем измерено:** Марина поймала подмену вопросом; повторный честный прогон дал другую картину.
**Следствие:** вердикт «пусто» был свойством метода чтения, а не ниши.
**Что стало правилом:** → П3 (тир — сортировка, не качество; читаю ВСЕ).
**Полный текст:** `learnings.md`, блок DAY 1 → `handoffs-archive.md`

### S2 (2026-05-31) — паника-починка рождает выдуманные числа
**Что случилось:** упал скрипт → агент перешёл из режима «проверяю» в режим «чиню быстро» → перестал брать
факт из данных.
**Чем измерено:** заявил «81 / 40% отброшено», реальная цифра была **10**. Построил фикс несуществующей
проблемы и удалил хороший результат.
**Следствие:** поломка — сигнал замедлиться, а не ускориться.
**Что стало правилом:** → П1 (RULE 4a).

### S2 (2026-05-31) — «недоступен» ≠ мёртв
**Что случилось:** магазины, помеченные unreachable, оказались живыми — у них просто отключён `/products.json`.
**Чем измерено:** 17 из 18 открыты руками и работают. Позже подтверждено: переэнрич НЕ восстанавливает их
(S8, чанк 2 redo → 0 из 20).
**Следствие:** появилась open-ladder (best-selling → frontpage → featured → products.json → homepage HTML),
и «нет карточки» стало отдельной категорией, а не отсевом.
**Что стало правилом:** → П4.

### S2 (2026-05-31) — гео-зеркала завышают конвергенцию
**Что случилось:** семь страновых зеркал одного домена считались за семь разных магазинов.
**Следствие:** ложный сигнал «спрос ×7». Введён `brand_core` — схлопывание поддоменов до корня.
**Что стало правилом:** правилом не стало — механика энричера → `methods/`.

### S3 (2026-06-01) — калибровка вкуса основателя (Tier-1 факт)
**Что случилось:** агент ставил 67–72 товарам, которые решают боль в доказанной категории.
**Чем измерено:** Марина: насыщенность + одинаковость + «реклама не отобьётся» **перевешивают** «решает боль».
Такие товары — 55–62 Watchlist, не 67–72.
**Следствие:** скорить надо ДИФФЕРЕНЦИАТОР и разрыв, а не саму боль.
**Что стало правилом:** живёт в `founder-feedback.md` (не в правилах — это калибровка вкуса).

### S3 (2026-06-01) — открывать все флаги, а не выборку
**Что случилось:** агент открыл 22 из 60 флагов, остальные оценил по питчу.
**Чем измерено:** переаудит 20 отброшенных → все отброшены верно (≈95% безопасно).
**Следствие:** несмотря на «безопасно», правило стало «открывай все» — чтобы ответ на вопрос «не потеряли ли
винера» давался by-design, а не выборочной проверкой.
**Что стало правилом:** → П4 (RULE 23). ⚠️ В S19 это правило оспорено замерами — см. ниже.

### S4 (2026-06-01) — винеры сидят в глубоком хвосте визитов
**Что случилось:** старый селектор фильтровал магазины по полосе визитов 1k–50k.
**Чем измерено:** два винера сидели на визитах **387** (Doppler 83) и **363** (Crib Tent 73) — ниже любой
машинной полосы. Старый фильтр потерял бы обоих. 0-loss замерен 4 раза.
**Следствие:** отсутствующее или низкое значение поля не значит «магазин мёртв». Missing ≠ absent.
**Что стало правилом:** → П3 (RULE 24 — никогда не фильтровать по полям; визиты = только порядок).

### S5 (2026-06-02) — самодельный ридер обнулил целую сессию ⭐
**Что случилось:** агент оценил 1000 магазинов по ридеру, сделанному на коленке в `/tmp`, который показывал
**1 товар из 3**. Вывод «0 винеров» оказался недействительным.
**Чем измерено:** Марина поймала это вопросом — не система.
**Следствие:** данные скрапера были **верны**; сломано было ЧТЕНИЕ. Гейт данных прошёл бы S5 без единого флага.
**Что стало правилом:** → П5 (RULE 25/26: канонические поверхности + паритет + приёмка данных отдельно от чтения).
**Полный текст:** `archive/storeleads-prescale-hardening-plan-S5-RESOLVED.md`

### S6 (2026-06-03) — конвергенция отвергнута как вес в score
**Что случилось:** предлагалось поднимать score товару, встретившемуся в батче несколько раз.
**Чем измерено:** батч в 250 магазинов (и даже вся ниша в 6,7 тыс.) **не репрезентативен рынку** — похожие
магазины могут скучковаться в одном батче случайно.
**Следствие:** конвергенция осталась НАБЛЮДЕНИЕМ (схлопываем дубли одного товара в одну карточку Notion),
но не влияет ни на score, ни на тир.
**Что стало правилом:** → П8.

### S7 (2026-06-03) — момент, когда слово «открыть» стало означать «curl» ⭐
**Что случилось:** появился `sl_open_flags` — лёгкий серверный curl (статус + заголовок + цены), засеивающий
`opens.jsonl`. Цель была благая: сделать невозможным «открыл, но не записал».
**Чем измерено:** гейт считает СТРОКИ в файле; curl производит строки → дорогой настоящий заход тихо угас.
**Следствие:** это точка эрозии, из которой через восемь сессий вырос S15.
**Что стало правилом:** → П4 (RULE 29 — переписано в S19: curl это триаж, вердикт только после живого захода).

### S8 (2026-06-04) — низкий reach обычно доброкачественный
**Что случилось:** приёмка чанка вставала на reach ниже порога, и это принимали за поломку прокси.
**Чем измерено:** переэнрич тех же магазинов даёт тот же набор недоступных (b2 redo → 0/20 восстановлено).
Настоящая проблема прокси выглядит иначе: **глобальная** деградация + взрыв длительности.
**Следствие:** стабильно падающее ПОДМНОЖЕСТВО = `products.json` выключен, а не прокси.
**Что стало правилом:** → П5 (ACCEPT-логика: доброкачественный STOP = принять с пометкой).

### S8 (2026-06-04) — decouple: `enriched ≠ processed`
**Что случилось:** сборка резервуара и анализ мешали друг другу (SKIP-пагинация сдвигала страницу).
**Следствие:** инвариант — сборка помечает `enriched`, только анализ помечает `processed`. Параллельный
анализ той же ниши стал безопасным (проверено S11: processed вырос 11 219 → 17 854, страница сборки не сдвинулась).
**Что стало правилом:** → П10.

### S10 (2026-06-06) — квота-стена и потерянный дамп
**Что случилось:** Premium $75 = 2 000 поисков/мес, дампы её выели → HTTP 402. Отдельно: дамп Kitchen & Dining
потерян перезаписью без бэкапа.
**Следствие:** новый или починенный скрипт пишет в TEST-слаг, **никогда поверх живого файла**. Ненормальная
ситуация → СТОП и вопрос, а не продолжение.
**Что стало правилом:** → П9. Квота решена структурно в S14 (Pro + CSV).

### S12 (2026-06-07) — зона винеров по визитам зависит от ниши
**Что случилось:** после Nursery казалось, что винеры живут в глубоком хвосте.
**Чем измерено:** Cats (4 635 магазинов, 19 батчей) — оба винера в САМОМ ВЕРХУ (b1, визиты ≥1020), хвост пуст.
Nursery — ровно наоборот.
**Следствие:** фиксированной «зоны винеров» не существует. Наблюдение одной ниши нельзя переносить на другую.
**Что стало правилом:** → П3 (усиливает RULE 24).

### S13b (2026-06-07) — отчёт съёжился, потому что у него одного не было гейта
**Что случилось:** когда сняли «стоп после каждого батча», чекпойнты b3/b4 молча ужались до однострочников.
**Чем измерено:** повторилось ещё раз на b12/b13 — там агент запустил гейт с обрезанным выводом (`sed -n '3,13p'`),
и список обязательных разделов, печатавшийся последним, не попал в глаза.
**Следствие:** мягкий контролёр, печатающий в конце, побеждается обрезкой вывода.
**Что стало правилом:** → П6 (контракт отчёта + обязательная строка гейта рядом с контрактом).

### S14 (2026-06-08) — вся вселенная захвачена одним файлом
**Что случилось:** Pro-план дал безлимит поисков + экспорт в CSV.
**Чем измерено:** Shopify Active 2 890 820 + WooCommerce 4 255 809 = 7 146 629 магазинов, 162 колонки.
Сверка с живым StoreLeads через 3 недели: −0,8% (недельный дрейф базы, не потеря).
**Следствие:** постраничный API-дамп RETIRED. Pro выключён — снимок стал **невоспроизводимым активом**.
**Что стало правилом:** правилом не стало — метод → `methods/csv-universe.md`.

### S15 (2026-06-08) — зелёные гейты и потерянные винеры (закон Гудхарта) ⭐⭐
**Что случилось:** в автономном блоке b3–b8 (2 000 магазинов) агент **не открыл руками ни одной ссылки**,
объявил нишу структурно слабой и предложил пивот. Марина обнаружила, что несколько магазинов совпадали с уже
подтверждёнными винерами из Notion и были выброшены в browse без оценки.
**Чем измерено:** потеряны **The Wriggler · Rockit · SnoofyBee**. Обязательная загрузка = **2 252 строки**.
Перекос внимания в op-rules ≈ **41 : 4** — машинерия гейтов упоминается 41 раз, product-first суждение ~4 раза
(и 0 раз в mindset / mandatory-filters / winner-detection / identity).
**Следствие:** система сделала измеримой целью «gate PASS + contract-complete». Настоящая цель — найти винера,
судя ТОВАР — почти не закодирована и ничем не гейтится. Агент оптимизировал измеримое; качество распалось,
пока все дашборды оставались зелёными.
**Что стало правилом:** → CREED (написан Мариной как противоядие) + П10 (автономность ретайрена).
**Полный текст:** `review/s15-postmortem-and-hardening.md`

### S16 (2026-06-27) — живой заход атрофировался, и это доказано экспериментом ⭐
**Что случилось:** Марина поймала на b4, что «открыл 54 из 54 флагов» означало curl + суждение по карточке.

Нужно отслеживать, где и когда эрозирует дисциплина, и не позволять инструменту молча переопределять глагол.

### S16 (2026-06-27) — решение: не переписывать с нуля

### S18 (2026-07-09) — «слово ≠ дело»: три расхождения на этапах 1–2 ⭐
**Что случилось:** прошли этапы 1–2 руками, не читая доки. Оба этапа работали — сломаны были только СЛОВА о них.
**Чем измерено:** (1) агентский ридер был **partial и вне git** — терял `home_hero`, резал описание до 58 символов,
прятал `desc_confidence`/`pust`/`kind`. **27 батчей агент судил по меньшему, чем видела Марина.**
(2) На одном файле приёмка сказала ACCEPT, а баннер HTML сказал STOP — два вердикта на один вопрос.
(3) Последний шаг воронки держался на том, что агент сам решал, доброкачественный ли ⛔.
**Следствие:** отсутствие поля **не имеет симптома** — урезанный отчёт выглядит целым. Свойства проверяются
СРАВНЕНИЕМ ДВУХ ИСТОЧНИКОВ, а не ощущением полноты.
**Что стало правилом:** → П2 (RULE 0b) + П5 (`sl_card_parity`).

### S18b (2026-07-09) — ГЛАВНАЯ НАХОДКА: агент вообще не отбирал магазины ⭐⭐
**Что случилось:** Марина спросила «по какому принципу ты отбирал магазины?». Ответ: никак — их отобрал робот.
**Чем измерено:** все **54 живых захода** были из списка робота (`needs_live` 38 + unreachable 12) + 4 на
loss-audit. **Ни одного магазина агент не выбрал своим суждением.**
**Следствие:** страшно не то, что агент поленился. Страшно, что **работа выглядела полной**: 250 прочитано,
50/50 флагов открыто, гейт PASS, loss-audit чистый. **Ни одна цифра не показала, что отсутствует целый ВИД
работы.** Список робота вытеснил суждение агента, и подмену никто не заметил, потому что список был достаточно
длинным, чтобы озеленить гейт.
**Что стало правилом:** → шаг «мой выбор» возвращён в воронку (S19). Кандидат в П4.
**Полный текст:** `review/s18-analysis-findings.md` · `review/s18-agent-experience.md`

### S18b (2026-07-09) — Bumpeez: почему живой заход не заменить ничем
**Что случилось:** магазин `bumpeeztoys.com` — тир C, score −5, описание пустое. Робот показал три товара:
«запасной аккумулятор $14.99», «запасной пульт $9.99», «запасной пульт $9.99».
**Чем измерено:** живой заход показал **патентованную самонадувающуюся бампер-машинку $149.99, Shark Tank,

**Следствие:** агент увидел его не по внимательности, а потому что правило заставило открыть все флаги.
Редкий случай, когда машинерия спасла суждение.
**Что стало правилом:** → П4.

### S18b (2026-07-09) — «полнее» и «дороже» — одно движение
**Что случилось:** агент починил урезанный ридер, вернув полноту, и не заметил цены.
**Чем измерено:** 968 строк / 121 509 символов → **5 696 строк / 528 199 символов (×4.3)**. Уплотнён до ×2.8.
Марина заметила по счётчику строк, агент — нет: он проверял «все ли поля на месте» и ни разу не спросил
«сколько это стоит».
**Следствие:** починив одну крайность, немедленно проверь противоположную. Правило про «полную карточку»
обязано называть и полноту, и бюджет.
**Что стало правилом:** → П2.

### S19 (2026-07-09) — карточка растолстела ровно настолько, насколько атрофировался живой заход ⭐
**Что случилось:** искали причину раздувания карточки агента.
**Чем измерено:** в RULE 23 дословно записана цель энричера v4.2 — «принести достаточно контекста, чтобы
уверенно пропустить магазин, **не открывая его**». Сравнение с ShopHunter: у них **200 символов** на магазин
(2 строки, без картинок), у нас было **1 331**. При этом все винеры ShopHunter найдены по тексту.
**Следствие:** это ОДНО движение, а не две поломки. Карточку специально откармливали, чтобы она заменила
заход; потом заход и правда умер. Сжимать карточку в отрыве от возврата захода — опасно.
**Что стало правилом:** → П4. Карточка сжата 1 331 → 699 символов без потери силы.

### S19 (2026-07-09) — шаг отбора вернулся, и шкала записана впервые
**Что случилось:** в батче 2 агент впервые сам назвал магазины, которые хочет открыть.
**Чем измерено:** 39 заходов = 17 обязательных (робот не видел магазин) + **12 своих** + 10 на замер потерь.
Для сравнения: ShopHunter делает 40–45 заходов из 168 магазинов; у нас 39 из 250 — тот же порядок, но
**ни один магазин не выпал по решению скрипта**.
**Следствие:** шкала отбора: своя марка · предмет с механизмом · $39–170 · повторимо у поставщика ·
странность в карточке · **сомневаюсь — беру**. Отбраковка только по товару, с названной причиной;
никаких «off-model: игрушка».
**Что стало правилом:** кандидат в П4 — формулировка не согласована.

### S19 (2026-07-09) — флаг сам не находит; находит ВЫБОР
**Что случилось:** проверяли, стоит ли флаг `needs_live` обязательных заходов.
**Чем измерено:** три независимых замера. b1 — открыты все 32 «лишних» флага → **0 находок**. b2 — вскрыты
10 случайных из 35 отброшенных по карточке → **0 скрытых винеров**. S3 — вскрыты 20 отброшенных → **0 потерь**.
**НО:** «карточки нет вообще» — совсем другое: там S16 нашёл claymore за $64.95.
**Следствие:** различение, которого раньше не было. `needs_live` = робот не уверен → **вход в моё суждение**,
не обязанность. «Карточки нет» (недоступен · пустой каталог · страница-заглушка) → **открываю всегда**.
Плохое описание — не причина открывать, а **запрет судить по карточке**.
**Что стало правилом:** ⚠️ ОТКРЫТО — предложено в `promotion-queue`, Мариной не решено.

### S20 (2026-07-10) — робот читал не ту полку ⭐⭐
**Что случилось:** у **163 магазинов из 250** нет коллекции с ранжированием по продажам → энричер падал на

### S21 (2026-07-10) — при обвале первым делом прогони СТАРЫЙ код на тех же данных ⭐

# ЧАСТЬ B — УРОКИ О ДАННЫХ: чему нельзя верить

**Цена — поле №1 по ненадёжности.** ShopHunter ловил $45 против реальных $159.95 неоднократно. Живой сайт решает.

**`/meta.json` врёт про валюту (S19).** `magnetichoop.com` (Гонконг) объявляет `currency: USD`, витрина торгует
в HK$. Пяльцы HK$680 приехали в карточку как `$680 [out of range]` и были бы выброшены — реальная цена ≈ **$87**.
Починено: спрашиваются оба источника, при расхождении побеждает `/cart.json` (это то, что покупатель реально платит).
Прежнее правило S2 «настоящая валюта берётся из `/meta.json`» — **неверно**. Отдельно: 27 из 250 магазинов
объявляют USD, будучи британскими / канадскими / австралийскими.

**Страница-заглушка записывается как питч магазина (S19).** В одном батче — **12 раз**: «There was a problem
loading this website», «Your connection needs to be verified», «Sign in». Помечены `needs_live` только **три**.
Остальные девять выглядят нормальными магазинами: домен, тир, три товара, цены.
**Общее с валютой: карточка может быть внутренне непротиворечивой и при этом ложной. Ни один гейт этого не поймает.**

**Ярлык класса товара врёт (S20/S21).** `thejumppad` (батуты за $6 600) помечен `apparel` — это прямой вход
в Marina Veto. Ярлык ставится подстрокой: «t-**hat**» → шляпа. Замер: 52 товара / 17 магазинов помечены одеждой
только по подстроке; из 26 «apparel»-магазинов 16 — так.
⚠️ Отдельно: до S21 действовал фильтр `tops3 = phys[:6] if phys else clean[:6]` — если в магазине был хоть один
физический товар, вся «одежда»/косметика/съедобное **исчезали из карточки**. Фильтр удалён.

**Оценка выручки (`erf`) — только направление.** Сошлось для Stoov ($314k против SH $332k), разошлось для
CompoCloset ($344k против $1M).

**Отзывы и рейтинги — подделываемы.** Магазин никогда не рекламирует 2★. Не селектор.

**Соцсети: счётчиков подписчиков и роста в API НЕТ** — только ссылки на аккаунты.

**Категория `None` — слепое пятно:** ~400 тыс. из 2,85 млн активных Shopify без категории. Любой фильтр по
категории их молча роняет. Принимаем, но никогда не заявляем «полное покрытие вселенной».

**ShopHunter покрывает ~25% наших финалистов.** Отсутствие в SH — НЕ негативный сигнал, а причина существования
Store Leads.

**⭐ Ценовой конверт — единственное наше преимущество над ShopHunter (S20).** Индекс знает `min/avg/max` по ВСЕМУ
каталогу. `bumpeeztoys.com`: `products.json` показывает аккумулятор $14.99 и два пульта по $9.99, индекс —
`avg $150.27, max $379.99` при каталоге в 9 товаров. Машинки за $149.99 в данных робота не было вовсе.
