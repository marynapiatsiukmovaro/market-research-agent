**Карта «где что физически лежит».** Создан в S17 после того, как агент на старте сессии пошёл искать

# 2. `methods/csv-export.md` — 95 строк

## Что это
**Инструкция, как была добыта вселенная.** Store Leads — это Vaadin-SPA, где наивные клики Playwright
не работают. Метод искали долго; файл фиксирует, что именно сработало, чтобы никогда не выводить заново.

## Что внутри

**Механизм по шагам:** отфильтровать в боковой панели (фильтр кодируется в URL) → открыть диалог экспорта
(кнопка не `<button>`, ищется по тексту) → **выбрать ВСЕ поля = 162 колонки** (четыре группы, у каждой своя
ссылка «Select All», часть НИЖЕ СГИБА — кликать все через JS независимо от видимости, иначе потеряется целая
группа) → нажать **настоящую** кнопку Export внутри оверлея (есть **обманка** на уровне страницы: если нажать
её, скачается файл на 16 байт вместо данных) → асинхронная задача, файл течёт потоком 3–4 минуты на 3 млн строк.

**Как запустить** — одна команда. **Проверка полноты:** колонок должно быть 162; если 141 — потеряна группа
Product Fields. Счёт строк: сырой счётчик строк **завышает** (в описаниях есть переносы внутри кавычек),
настоящая цифра считается парсером CSV.

**Грабли:** копировать скрипт на сервер перед каждым запуском (устаревшая копия дала 141 колонку) ·
счёт строк ≠ счёт магазинов · не расширять окно в надежде, что кнопка станет видимой — не станет ·
один аккаунт = одна задача экспорта за раз.

## ✅ Вердикт ПОДТВЕРЖДАЕТСЯ: оставить почти как есть

**Этот файл — эталон того, как должен выглядеть файл этапа.** Ровно нужный жанр: что делать, как проверить,
какие грабли. Никакой истории, никаких пересказанных правил. На него стоит равняться, переписывая остальные.

Два уточнения:
1. **Сверху нужна честная пометка о статусе.** Pro-план выключен, переэкспорт невозможен без его включения.
   Значит, это **не текущая процедура, а инструкция на случай «если снова понадобится свежая вселенная»**.
   Без этой пометки агент решит, что так надо делать каждый раз.
2. **Блок «где теперь лежат файлы» — дубль `data-inventory`.** Оставить сами координаты здесь (это свойство
   актива), а из `data-inventory` его убрать — иначе два источника разойдутся.
3. Раздел «Грабли» **остаётся внутри файла** — по нашему критерию это постоянные свойства процедуры
   («копируй скрипт перед запуском» — всегда), а не отклонения.

# 3. `methods/interface-guide.md` — 123 строки

## Что это
**Как устроен внутренний API StoreLeads.** Панель — это SPA на Shadow DOM, где текст страницы пуст, но
за ней стоит чистый JSON-API, к которому мы обращаемся напрямую с залогиненной сессией.

## Что внутри

| Блок | Строк | Содержание | Живое? |
|---|---|---|---|
| Статус | 5 | что живое (логин, счётчики фильтров), что retired (постраничный дамп) | ✅ |
| **Доступ и вход** | 20 | passwordless-логин по коду на почту · **приём с FIFO**, позволяющий агенту провести двухшаговый ввод через одно соединение · ловушки: пустой текст страницы даёт ложный «не залогинен», не убивать процесс по маске — убьёшь своё же соединение | ✅ **живое и ценное** |
| Два слоя фильтров | 25 | простые `f:` и продвинутый `bq` (движок Bleve): категория через `match`, не `term` · многозначная страна через запятую даёт НОЛЬ (работает как И, не ИЛИ) · created ≥ 2020 только через строковый диапазон | ✅ нужно для живых счётчиков |
| Пагинация и потолок | 5 | 50 записей на страницу, жёсткий потолок 25 000 на запрос, обход через окна по дате создания | ⚠️ было нужно для дампа (retired); для счётчиков — да |
| **Поля магазина + покрытие** | 12 | какие поля приходят и **у скольких процентов магазинов они есть**: выручка 100% · визиты 100% · цена 96% · вес 86% · **отзывы 45%** · **рейтинг 27%** | ✅ **очень ценно** |
| Статус плана | 6 | Pro выключен, что это значит | ✅ → в `state.md` |
| **СПИСОК ВСЕХ СКРИПТОВ** | **30** | энричер, гейты, ридеры, селекторы, пометки, артефакты | ⚠️ **см. ниже** |

## 🔴 ГЛАВНАЯ НАХОДКА: реестр скриптов лежит внутри файла про API — и врёт

Последние 30 строк — это **список всех скриптов департамента**, а не интерфейс StoreLeads. Там перечислены
энричер, оба гейта, оба ридера, селекторы, пометка разобранных, генераторы артефактов. Это единственное
место в системе, где скрипты собраны вместе — и оно спрятано в файле, куда никто не пойдёт их искать.

**И список устарел:**
- описывает энричер с полем `needs_live` — **удалено из карточки в S20**;
- называет два ридера **каноническими** — это **версия до S20**, действующая лежит под именами с `_TEST`;
- упоминает временный ридер, который в S18 признан частичным и снят.

**Это и есть долг №1 в его исходном виде.** Мы собирались завести «единый блок имён скриптов, чтобы при
переименовании править одну таблицу» — **он уже существует**, просто лежит не там и не обновлялся.

## 💡 Предложение: `methods/scripts.md` — реестр скриптов

Одна таблица: **скрипт · этап · что делает · статус** (живой / legacy / retired / TEST-версия).
Что это даёт:
- переименование TEST → канон правит **одну таблицу**, а не шесть документов;
- сразу видно, какие скрипты осиротели (не названы ни в одном этапе) — как это было с файлами `core/`;
- файлы этапа перестают тащить в себе списки имён и остаются про суть.

## ⚠️ Вердикт СУЩЕСТВЕННО УТОЧНЯЕТСЯ

Было: «оставить, почистить от RETIRED». Правильнее — **разделить на три**:

| Часть | → Адрес |
|---|---|
| Вход, API, `bq`, потолки, поля | `methods/storeleads-api.md` — оставить, вычистить дамп |
| **Список скриптов** | **`methods/scripts.md`** — новый реестр (§3 выше) |
| Проценты покрытия полей | **дополняют карту доверия**: отзывы есть у 45%, рейтинг у 27% → «отзывы не селектор» получает цифру |
| Статус плана | `state.md` |
