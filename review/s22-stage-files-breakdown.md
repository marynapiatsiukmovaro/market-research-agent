# ЧАСТЬ 1 — `methods/subagent-spec.md` → `methods/card-contract.md`

## 1.1 Что это за файл простыми словами

**Техническое задание для скрапера.** Договор между роботом и агентом: что робот обязан выкопать про
каждый магазин и в каком виде положить, чтобы агент потом мог судить, не открывая каждый магазин заново.

Робот заходит на 250 магазинов и по каждому собирает карточку: какие товары, по какой цене, что это за
товар, как выглядит. Агент читает 250 карточек и решает, кого смотреть живьём.
**Робот скребёт факты, агент судит** — это разделение в файле прописано прямым текстом.

**Критерий успеха (слова Марины, прямо в файле):** карточка достаточно хороша, когда, читая её, агент
может уверенно сказать «этих беру дальше, эти точно не наши» — и быть готов к анализу, не переоткрывая
каждый магазин.

**Почему название путает.** «Sub-Agent Spec» — потому что идею взяли из ShopHunter, где предполагалось,
что карточки готовит суб-агент. По факту это делает **скрипт**. Название осталось от невоплощённой идеи.
→ Переименовать в `methods/card-contract.md`.

## 1.5 🔴 ЧЕГО НЕ ХВАТАЕТ, ЧТОБЫ ДОПИСАТЬ ЧЕСТНО

**Нужен один реальный файл карточек с сервера** — любой готовый `*_enriched.json` из подготовленных
чанков (лежат на VPS в `logs/storeleads/niches/...`). Из него за минуту видно, какие ключи там на самом
деле есть, и таблица полей пишется **по факту, а не по памяти**.

**По документам этот вопрос не решается в принципе.** Пока файла нет — можно подготовить всё остальное
(структуру, карту доверия, критерий успеха), оставив в таблице полей пометки «сверить по живому файлу».

на канонические имена. Любой честный агент прочитает спеку, запустит канонический скрипт и получит
СТАРУЮ карточку, не зная об этом.

## 2.3 ⭐ Что такое «карта доверия полям» — целиком

Это накопленное знание о том, **какие данные врут**. По каждому полю — вердикт:

| Поле | Вердикт |
|---|---|
| **Цена** (средняя / мин / макс из индекса) | **НИКОГДА не доверять, ВСЕГДА подтверждать на живом сайте.** Поле №1 по ненадёжности. ShopHunter неоднократно показывал $45 при реальных $159.95 |
| **Валюта магазина** | `/meta.json` **МОЖЕТ ВРАТЬ.** Живой случай: гонконгский магазин объявляет `USD`, торгует в HK$ → пяльцы HK$680 приехали как `$680 [вне диапазона]` и были бы выброшены; реальная цена ≈ $87. Прежнее правило S2 «настоящая валюта берётся из `/meta.json`» — **неверно** |
| **Оценка выручки** | только направление. Сошлась для одного магазина ($314k против $332k у ShopHunter), разошлась для другого ($344k против $1M) |

| **Какой товар главный** | **НИКОГДА не доверять автоподбору робота** — он хватает наборы, аксессуары, запчасти, особенно когда падает на общий список товаров |

| **Соцсети: подписчики и рост** | **в API их НЕТ вообще** — есть только ссылки на аккаунты |
| **Категория** | слепое пятно: около **400 тысяч из 2,85 млн** активных магазинов **без категории**. Любой фильтр по категории их молча роняет. Принимаем, но никогда не заявляем «полное покрытие вселенной» |
| **Кросс-проверка через ShopHunter** | ~25% попаданий. **Отсутствие в ShopHunter — НЕ негативный сигнал**, а причина, по которой Store Leads вообще существует |

## 2.3а ⚠️ ИСПРАВЛЕНО (Марина, S22): карта доверия — это НЕ контракт карточки

Проверил каждую строку по вопросу «кто и когда этим пользуется». **Карта не переезжает целиком —
она РАСПАДАЕТСЯ по этапам, и большая часть действительно уходит в Stage 3:**

| Строка карты | Кто пользуется | → Адрес |
|---|---|---|

| Какой товар главный — не доверять автоподбору | агент, когда читает карточку | **Stage 3** |
| Оценка выручки — только направление | агент, когда судит | **Stage 3** |
| Отзывы — подделываемы, не селектор | агент, когда судит | **Stage 3** |

## 3.1 ⭐ ПРАВИЛО ХРОНИКИ: ТИШИНА = НОРМА (Marina-locked S22)

**Формулировка для файла хроники, в шапку:**

> В хронику записываются **отклонения и частные случаи** — то, что пошло не так, чему научило,
> что из этого изменило систему. **Если про сессию или этап здесь ничего не написано — значит,
> всё прошло штатно.** Отсутствие записи — это НЕ пробел в памяти, это положительный результат.

**Зачем это правило.** Хроника состоит из разборов поломок — по природе жанра. Агент, прочитавший
подряд S5, S15, S16, S18, S20, S21, может решить, что **так происходит всегда**, и начать работать
с оглядкой на несуществующую катастрофу. Правило снимает искажение: перечисленное — это исключения,
и их перечислили именно потому, что они исключения.

**Где лежит фактическое состояние (а не хроника).** Что подготовлено и что проанализировано,
отмечается **на сервере** — это единственный источник правды по покрытию:
`processed_domains.json` (что разобрано) и `enriched_index.json` (что подготовлено).
Хроника этого не дублирует. В систему это попадает через `state.md` — цифрами, не рассказом.
